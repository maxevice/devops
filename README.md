# Лабораторна робота №1: Simple Inventory (mywebapp)

## 1. Варіант індивідуального завдання
Номер у списку (N) = 17.
* **V2 (Конфігурація та БД):** (17 % 2) + 1 = 2 -> Конфігураційний файл за шляхом `/etc/mywebapp/config.json`, СУБД PostgreSQL.
* **V3 (Тематика застосунку):** (17 % 3) + 1 = 3 -> Simple Inventory (Сервіс обліку обладнання).
* **V5 (Порт застосунку):** (17 % 5) + 1 = 3 -> Порт 3000.

## 2. Документація по застосунку
**Призначення:** Веб-застосунок `mywebapp` призначений для автоматизації обліку та зберігання інформації про інвентар (ID, Назва, Кількість, Час створення).
**Локальний запуск (для розробки):**
1. Створити віртуальне середовище: `python3 -m venv venv` та активувати його `source venv/bin/activate`.
2. Встановити залежності: `pip install fastapi uvicorn sqlalchemy psycopg2-binary python-multipart`.
3. У файлі `config.json` вказати параметри підключення до локальної БД PostgreSQL.
4. Виконати міграцію для створення таблиць: `python3 migrate.py`.
5. Запустити сервер розробки: `uvicorn main:app --port 3000`.

**API Ендпоінти:**
* `GET /` — (text/html) Головна сторінка зі списком посилань та формою додавання.
* `GET /health/alive` — Перевірка працездатності контейнера/сервісу (завжди повертає 200 OK).
* `GET /health/ready` — Перевірка готовності (тестує реальне підключення до БД PostgreSQL).
* `GET /items` — Вивести список усіх предметів в інвентарі (повертає лише fields: `id`, `name`).
* `POST /items` — Створити новий запис у системі обліку (приймає параметри `name`, `quantity`).
* `GET /items/{id}` — Вивести детальну інформацію по конкретному запису (повертає `id`, `name`, `quantity`, `created_at`).
*Залежно від заголовку `Accept` (text/html або application/json), API автоматично адаптує відповідь у формат красивої HTML-сторінки або чистого JSON.*

## 3. Документація по розгортанню
**Вимоги до інфраструктури (ВМ):**
* **Операційна система:** Офіційний чистий образ Ubuntu Server 24.04 LTS.
* **Ресурси:** 1 vCPU, 2GB RAM, 15GB жорсткий диск.
* **Мережа:** Режим NAT з налаштованим прокиданням портів (Host 2222 -> Guest 22 для SSH; Host 8080 -> Guest 80 для HTTP-трафіку Nginx).

**Інструкція з автоматичного розгортання:**
1. Склонувати або скопіювати папку проєкту на чисту віртуальну машину.
2. Надати скрипту розгортання права на виконання: `chmod +x deploy.sh`.
3. Запустити автоматизацію від імені суперкористувача: `sudo ./deploy.sh`.
4. Скрипт автоматично оновить систему, встановить PostgreSQL та Nginx, створить системних користувачів, налаштує конфігурації, виконає міграцію бази даних та запустить застосунок як системний сервіс через `systemd`.

## 4. Інструкція з тестування працездатності
1. **Перевірка веб-сервера:** Відкрити браузер на хост-машині за адресою `http://127.0.0.1:8080/`. Має відобразитися головна сторінка інвентаря.
2. **Перевірка ізоляції ендпоінтів:** Спроба отримати доступ до службових ендпоінтів стану (наприклад, `http://127.0.0.1:8080/health/alive`) ззовні має блокуватися Nginx із поверненням HTTP-коду `403 Forbidden`.
3. **Перевірка збереження даних:** Додати новий пристрій через форму, перейти в меню списку та перевірити деталі доданого об'єкта.
4. **Перевірка ескалації прав:** Увійти під створеним користувачем `teacher` або `operator` (дефолтний пароль `12345678`) та перевірити вимогу примусової зміни пароля при першому вході, а також рівень доступу до команд `systemctl`.

## 5. Запуск за допомогою Docker Compose (Лабораторна робота №2)
Проєкт повністю контейнеризовано. Для запуску системи не потрібно вручну налаштовувати середовище.

**Вимоги:** Встановлений Docker та Docker Compose.

**Інструкція з запуску:**
1. Клонуйте репозиторій та перейдіть у папку проєкту.
2. Виконайте команду для збірки та запуску всіх сервісів у фоновому режимі:
   `docker-compose up -d --build`
3. Застосунок буде доступний за адресою: `http://127.0.0.1:8080/`

**Особливості контейнеризації:**
* Усі сервіси (web, nginx, postgres) піднімаються в ізольованій мережі `mywebapp_net`.
* Дані бази даних зберігаються на диску у Docker Volume (`db_data`), що дозволяє їм переживати перезапуск системи чи видалення контейнерів.
* Nginx працює як reverse-proxy і маршрутизує трафік до контейнера `web`.
